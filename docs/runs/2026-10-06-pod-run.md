# Run report: the first real-model runs (2026-10-06)

The first end-to-end runs of aspire-si on real models. They had two jobs:

- **Dogfood.** Find what breaks when the documented path runs on real models.
- **Fixtures.** Produce real geometry exports for ScalarScope.

## Setup

| | |
|---|---|
| Hardware | 1 × RTX PRO 6000 (96 GB), rented through offrig's `job` profile, $2.09/hr; $3.84 in total |
| Student | `Qwen/Qwen2.5-1.5B-Instruct`, 4-bit, LoRA r16 on q/k/v/o |
| Critic | `head`, mean pooling over the student's last hidden layer |
| Prompts | the 32 in `examples/local-run/prompts.json` |
| Schedule | 3 dialogue turns (per-turn evaluation off), 3 epochs, batch 1, seed 42 |
| Code | commit `0972ef5`; configs, `setup.sh`, `train.sh`, `probe.py` and `drift.py` in `examples/pod-run/` |

There were two conditions:

- **real-local-teacher:** `Qwen/Qwen2.5-32B-Instruct` (4-bit) as the only teacher.
- **real-composite-teacher:** the same teacher plus `google/gemma-4-31B-it` (4-bit). The two vote, and each one's score is kept.

The two runs ran side by side on the one GPU: about 50 minutes for the local run and 80 for the composite.

## What broke

A first attempt was stopped after 15 minutes, because the real dialogues showed three bugs that would have corrupted both runs. Each is fixed and covered by a test; see the CHANGELOG, 1.2.0, Fixed.

- **The student's input was cut from the end.** It was cut at 512 tokens: the trainer never passed `student.max_length`. By the third turn the cue to answer was gone, so the student continued the dialogue mid-sentence, and that reply was what the teacher scored.
- **Complete evaluations fell back to 5.0.** The local teachers wrote LaTeX (`\(`) and raw newlines inside JSON strings, which a strict JSON parse rejects.
- **768 tokens cut verbose teachers off mid-JSON.**

The run also showed that a run stopped by a deadline would lose its whole geometry export. The export is now written after every epoch.

offrig, on the first live use of its `job` profile:

- **Lost environment.** An ssh session does not inherit the pod's environment, so the first downloads filled the container disk (offrig#3).
- **Shared alias.** One ssh alias is shared by every project, so a launch from another project collided with this one (offrig#2, fixed by offrig#5).

## Results

| | real-local-teacher | real-composite-teacher |
|---|---|---|
| Teacher scores (32 prompts) | mean 7.16, sd 0.62, range 6.0–8.0 | mean 5.45, sd 0.93, range 3.5–7.0 |
| Per teacher | — | Qwen 7.12, Gemma 3.78; agreement r = 0.53 |
| Critic loss, epochs 1 / 2 / 3 | 1.09 / 0.56 / 0.49 | 1.37 / 0.86 / 0.65 |
| Judge: "2+2 = 4" vs "it is 5" | 6.69 vs 6.05 | 4.75 vs 3.93 |
| Judge: Rayleigh scattering vs "the ocean reflects" | 7.20 vs 7.08 | 3.84 vs 3.89 |

**The critics learned little about quality.** Both critics approach the error of always predicting the mean score. Neither separates a right answer from a wrong one by much, and the composite critic ranks one wrong answer above the right one. With scores this narrow, the cheapest way for a critic to cut its loss is to learn the average.

### The hidden-state trajectory

**The per-step export plots which prompt each step drew.** At batch 1, each step's state is the pooled hidden state of one prompt and its response. Two prompts sit about 0.1 apart (mean cosine distance), roughly 10,000 times the total drift that three epochs of training cause. Epochs 2 and 3 also replay the cached epoch-1 scores, so the scalar curves and the dips repeat by construction.

**Probe trajectory.** To see what training did, `probe.py` sends the same 32 exchanges (each prompt with the response the teacher scored) through the base student and through checkpoint-1 to checkpoint-3. `drift.py` subtracts each exchange's base state, which removes prompt identity.

| Drift from base | real-local-teacher | real-composite-teacher |
|---|---|---|
| Mean size, checkpoints 1 / 2 / 3 | 0.45 / 0.58 / 0.66 | 0.46 / 0.65 / 0.68 |
| Each exchange keeps its direction (cosine, 1→2, 2→3) | 0.76, 0.85 | 0.61, 0.90 |
| Shared across exchanges (cosine to the mean drift) | 0.78 → 0.87 | 0.78 → 0.89 |
| Position along the drift axis vs teacher score | r = −0.05 | r = +0.22 |

**Training moved the student's representations in one shared direction that strengthens each epoch, but it is not a quality axis.** Neither correlation is beyond what a random direction gives (95th percentile of |r| = 0.32).

This is consistent with what the trainer does in 1.2.0. The critic's loss flows into the student's LoRA, so the representations shift to help the critic fit the teacher's scores. With narrow scores, that mostly means fitting their mean. The student is not yet trained toward better answers ([#11](https://github.com/mcp-tool-shop-org/aspire-si/issues/11)).

## The exports

ScalarScope's real fixtures are four files.

**Per-step exports** (`real-local-teacher`, `real-composite-teacher`):
- The trainer's own exports: 96 steps, covering all 3 epochs, 9 dimensions.
- The local export has 1 professor; the composite has 2.

**Drift exports** (`*.drift`), written after the run by `probe.py` and `drift.py`:
- 96 steps: checkpoints 1–3 × the 32 exchanges, in a fixed order, checkpoint-major.
- Each state is that exchange's change from the base student.

## What comes next

The planned experiment is recorded on #11:
1. A LoRA fine-tune on the same material.
2. The same ASPIRE config and seed, starting from that fine-tune.
3. A comparison against these runs.

It needs:
- the student trained by the critic;
- dialogues regenerated every epoch;
- a fixed probe set recorded during training (the recorder should pool the probe set, not the training batch);
- answers with a real spread of quality, so that the critic has something to learn beyond the mean.
